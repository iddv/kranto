# Support

Kranto is maintained by one person in their spare time. There is no paid support and no
guaranteed response time.

- **From the app:** **Feedback** in Kranto's header sends a bug, an idea or a question here as
  an issue from you, with the details it shows you first (Help › Feedback).
- **Questions and ideas:** GitHub Discussions on this repository, when they are enabled;
  until then, an issue.
- **An error Kranto showed you:** press **Send this error** on the row or page that says it
  (it shows the report before sending), or run `kranto report` and attach the file it names.
- **A bug:** open an issue with the **Bug** form. It asks for `kranto --version`, your
  distribution, the model provider and the output of `kranto doctor`. Remove keys, tokens and
  delivery URLs first: issues are public.
- **A source that should be supported:** use the **Source request** form.
- **Something Kranto should do:** use the **Feature** form, which asks for the problem first.
  [docs/scope.md](docs/scope.md) lists what Kranto will not become.
- **A security problem:** never in a public issue. See [SECURITY.md](SECURITY.md).
- **Conduct:** see [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).

Model calls spend money on your provider account, within the budget you set. The project
cannot refund or reimburse spend.
